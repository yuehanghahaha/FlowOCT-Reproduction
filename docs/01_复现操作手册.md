## 3. 你已有数据的目录

把原始文件复制/移动到：

```text
D:/data/code/keyan_fuxian/FlowOCT/data/OCTA500/raw/
├── OCTA_3M/   保持原始结构
└── OCTA_6M/   保持原始结构
```

作者代码**不会直接读取这个 raw 文件夹**。训练读取如下准备格式：

```text
data/OCTA500/prepared/
├── train/
│   ├── patient_A.npz
│   └── patient_B.npz
├── validation/
│   └── patient_C.npz
└── test/
    └── patient_D.npz
```

每个 `.npz` 必须含：

```python
oct  # 三维数组，单模态；不要提前加 channel 维
octa # 三维数组，与 oct 相同 shape 和配对网格
```

加载器自己加 C=1，DataLoader 再加 B。不要保存 `(1,D,H,W)`，否则会多出维度。输入应有限值且非常量，否则当前 min-max 会产生 NaN。

如果你已经有正确的 `.npz`，直接按患者划分放到 prepared 三个集合即可，不需重复转换。

### 3.1 划分原则

论文报告 3M 的 train/validation/test 数量为 140/10/50；6M 为 180/20/100（正文 4.1）。仓库没有提供患者 ID 清单与确切预处理转换脚本。仅分成同样数量不等于复现相同划分。

如果拿不到原始划分，使用可公开记录的患者级固定划分，并将结果称为“自己的协议下重实现”。同一患者双眼、随访、多个扫描要作为一组。先分患者，后生成 patch/slice。3M/6M 建议分别保留 prepared_3M、prepared_6M，并给命令指定不同根目录；当前 prepared 可先放一个 FOV。

用 `experiment_templates/patient_manifest.example.csv` 建立真实清单，**替换全部 EXAMPLE/REPLACE 行**，不要将样例当正式记录。

### 3.2 轴顺序和配准是开始训练前的第一关

数据集标注的体尺寸通常采用自己的轴顺序。`(400,400,640)` 这三个数不能告诉你哪个轴是 scan index、axial depth、lateral location。

确认方式：读数据说明与 spacing；观察三个方向的中间切片；检查沿哪个轴看到视网膜层；查看每张原始 B-scan 对应索引；验证 OCT/OCTA 同一坐标位置。再记录变换，而不是为了“变成 D,H,W”凭感觉 transpose。

当前加载器把第三维空间长度 resize 为 `crop_size`，将另外两维 resize 为 `load_size`。后续抽第一个空间轴的 slice。若轴定义错了，所谓“深度对齐”和“en-face projection”都会失去物理解释。图像 `.npz` 没有保存 affine/spacing，必须在旁边记录 metadata。

配准检查至少抽样比较同一患者的切片、层边界、投影位置。相同 shape 不能证明对齐。当前项目不提供 registration 算法；不要默认无需检查。

## 4. 转换工具怎样用

`tools/pack_pair.py` 支持：一个 `.npy` 三维体，或一个患者的原生灰度 BMP/PNG/TIFF 切片文件夹。它自然排序文件名，因此 2 排在 10 前；要求两模态切片名字完全一致，并拒绝自动把 RGB 转灰度。

它不能推断解剖方向，也不做配准/归一化。MAT/NIfTI 必须先检查变量名、shape、affine；不要用通用转换猜键名。

示例（**路径与轴描述必须根据你的实际数据修改**）：

```powershell
python tools/pack_pair.py `
  --oct 'data/OCTA500/raw/OCTA_6M/OCT/PATIENT_ID' `
  --octa 'data/OCTA500/raw/OCTA_6M/OCTA/PATIENT_ID' `
  --output 'data/OCTA500/prepared/train/PATIENT_ID.npz' `
  --patient-id PATIENT_ID --split train `
  --transpose 0 1 2 `
  --axis-description '填写已核对的三个输出轴物理意义'
```

这里 `0 1 2` 只表示保持输入顺序，**不承诺正确的解剖顺序**。脚本会另存同名 JSON，记录源文件、transpose、轴描述等。若两模态命名不同，它会停止，你需要明确建立 slice ID 映射，不能任意忽略检查。

首个患者转换完先看三向切片、配准、强度范围，再批量转换。工具拒绝覆盖已有结果。

检查准备格式：

```powershell
python tools/check_dataset.py --dataroot data/OCTA500/prepared
# 完整真实清单准备好后：
python tools/check_dataset.py --dataroot data/OCTA500/prepared --manifest '你的患者清单.csv'
```

检查内容：集合非空、键名、三维同形状、NaN/Inf、常量体、跨集合完全相同的数组；有 manifest 时检查 patient_id 跨 split。**该工具不证明清单与文件一一对应，也不能识别近重复或配准错误**，需要人工审核清单完整性。

## 6. 真实数据先跑小尺寸一轮

推荐使用单独的 `working/` 最小修正版：它只修投影ROI索引，原始源码保留在upstream。补丁与验证见《已验证结果与代码审计》。下面的真实数据命令使用working目录；如果专门对照作者原件，可换upstream并明确记录。

先采用已验证能执行的 32³ 尺寸：

```powershell
Set-Location 'D:\data\code\keyan_fuxian\FlowOCT\working'
python train.py `
  --dataroot '../data/OCTA500/prepared' `
  --name real_small_debug --gpu_ids 0 `
  --load_size 32 --crop_size 32 --batch_size 1 `
  --num_threads 0 --n_epochs 1 --print_freq 1 `
  --val_epoch_freq 1 --save_epoch_freq 1
```

这会大幅 resize 数据，是调试程序格式用的，不能评价细毛细血管或替代原分辨率科研实验。若两个集合有很多患者，先用独立的 `debug_prepared/` 放 2 个 train、1 个 validation、1 个 test，保持它们来自不同患者。

成功标志：loss 全部有限，验证集非空，checkpoint保存，预测形状正确。看视觉误差、强度和位置，不只看总 loss。

再尝试 `load_size=64,crop_size=64`。尺寸一般选 16 的倍数，保证二维 Haar 后还有足够的 U-Net 下采样空间。6GB 上是否能用 128 或 256 必须实际测；当前原模型默认一次将 D//4 张切片作为网络 batch，crop增大会同时提高 slice 数与空间成本。

**不要直接启动默认 400 epochs。** 先查明数据和评价正确，再确定训练预算。论文写 200；当前代码默认 400；默认也没有学习率衰减实现。

## 7. 怎样测试已经训练的权重

训练没有保存 `latest_net_G.pth`，所以测试默认 `--epoch latest` 会找不到文件。先看：

```powershell
Get-ChildItem './checkpoint/real_small_debug/*_net_G.pth'
```

从实际文件名去掉 `_net_G.pth`，把剩余完整标签传给 `--epoch`。例如保存的是 `best_epoch_001_psnr_XX_ssim_YY_net_G.pth`，标签就是 `best_epoch_001_psnr_XX_ssim_YY`，不是单纯 `1` 或 `best`。

下面命令里的占位符必须替换为真实标签：

```powershell
python test.py `
  --dataroot '../data/OCTA500/prepared' `
  --name real_small_debug --gpu_ids 0 `
  --load_size 32 --crop_size 32 `
  --epoch '填写实际权重完整标签'
```

`load_size/crop_size` 必须和你定义的评价协议一致。结果在 `results/name/epoch/`，键为 `oct`、预测 `octa`、真实 `octa_gt`。**这是 resize/crop 后的体，不是自动恢复的原体积**。当前 test loader 固定 1 worker，`--num_threads` 不会改变它；训练的 workers 可设为 0。

实际生成器不需要 GT，但作者 `test.py` 和 dataset 仍要求配对 `.npz` 含 octa。单独只有 OCT 的部署输入需要另写加载器，不要把 test.py 当成已经完成单模态部署。

回根目录：

```powershell
Set-Location 'D:\data\code\keyan_fuxian\FlowOCT'
python tools/visualize_results.py --input 'working/results/real_small_debug' --output 'artifacts/real_small_debug/figures'

```

可视化显示三个**数组索引平面**与绝对误差，不在未确认轴含义时称它们为轴位/冠状位等。

新增评价明确采用 `data_range=1`、3D SSIM `win_size=7`、每文件独立计分。GT阈值前景只是一种示范协议，不是论文的前景区域算法，也不是人工血管标签；阈值应在验证集确定并冻结。同步报告背景误差与全体指标，避免只在 GT 前景计算而看不见假血管。

脚本每文件平均。只有“一文件=一独立患者”成立时才能称为患者 macro；多眼、多扫描请先按患者聚合。LPIPS/FID、分层投影、下游诊断不在这个简单评价工具里，不能声称复现了论文完整表格。

## 9. 继续训练的限制

`--continue_train --epoch 标签 --epoch_count 轮数` 只加载网络参数；没有 Adam状态、随机状态、scheduler/global_step。它属于 warm start，**不等于中断前逐步精确恢复**。训练名称默认也没有记录随机 seed。

正式项目需把网络、optimizer、scheduler、scaler、epoch、global_step、随机状态、配置、数据清单 hash 保存在同一个 checkpoint，并验证加载前后预测一致。

## 10. 常见错误速查

| 现象 | 先检查什么 | 处理 |
|---|---|---|
| `No module named pywt` | 是否用 flowoct 环境 | 安装 PyWavelets；原 requirements未显式列出 |
| `No module named matplotlib` | 可视化依赖 | 用已建立环境或补 matplotlib |
| `latest_net_G.pth` 不存在 | 实际保存标签 | 指定完整 `--epoch` |
| `num_samples should be positive` | train没有 `.npz` | raw不直接读；检查 root/train 和键名 |
| 验证除零 | validation为空 | 必须用 validation 目录，不是 val |
| loss NaN | 常量体、NaN、归一化分母 | 先数据检查；研究版加常量策略 |
| CUDA out of memory | slice batch=D//4、输入尺寸、推理chunk32 | 减尺寸用于调试；研究版新增明确的 slice 数/chunk控制 |
| CPU/GPU device mismatch | 小波矩阵的 `.cuda()` | 本机先CUDA；研究版按输入device创建矩阵 |
| U-Net concat尺寸不匹配 | H/W经过DWT和多次下采样 | 首先用已验证32或64；修改尺寸前检查每层 |
| loader启动卡住/报错 | Windows multiprocessing | 训练用 `num_threads=0`；原 test 需修改固定worker才改变 |
| 数据 axis看起来错乱 | transpose与切片顺序 | 回到原始metadata；不靠shape猜方向 |
| 验证分数高、血管模糊 | 大面积背景和resize | GT固定ROI、血管结构、原尺度评价 |
