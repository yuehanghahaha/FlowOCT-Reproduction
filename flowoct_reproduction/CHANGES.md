# 每一类改动、理由与结果含义

## 2026-10-21：A100无需手工编辑配置的部署入口

新增 `a100.py`：从数据目录中解压即可自动定位CSV所在位置，默认使用进程内 `cuda:0`，以原配置为模板只填写实际CSV绝对路径和设备。`check`顺序完成GPU/版本检查、清单审计、正式尺寸单步、保存/重载/推理/评价诊断；`train`调用原来的200轮训练；`resume/test`使用run保存的配置，不重新选择数据。多份数据、空上传目录或已有实验不会被静默选用或覆盖。

理由：用户已把除native外的数据上传到名为 `OCTA500_v1` 的目录，希望上传代码包后不再手工处理代码和JSON。新包解压为 `flowoct_reproduction_a100`，避免与旧代码目录混淆。安装环境仍按平台权限执行，不自动连接服务器。

新增 `tests/test_a100.py` 验证目录改名/缺少native、多个数据候选、空目录、配置只改路径与设备、恢复使用原配置和已有run保护；维护脚本 `build_provenance.py` 增加新入口的源码指纹。新增 `A100_START.md` 说明操作。模型、小波、损失、加载器和训练循环文件全部保持本次修改前的字节内容，64张整批、无激活重计算、FP32、200轮及原checkpoint规则不变。

## 当前采用的复现口径

按用户进一步明确的要求，**模型、小波、损失及其权重以作者公开二维代码为基准；训练预算采用论文的 200 epochs；评价参考论文指标并明确尚未补齐的部分。** 不把论文文字与代码的差异自行改写成三维主干或另一套损失。

初次交付默认启用了 `network_chunk=4/inference_chunk=4`。现已将两份正式配置改为作者执行方式 `network_chunk=0/inference_chunk=32`，保留 200 epochs。默认不会调用激活重计算，仍将 64 张片一次送入主干。可选分批代码保留供审阅，仅显式传入 `--network-chunk 4` 才会启用；当前复现方案不启用。

本次只调整配置、启动脚本和说明，模型、小波、数据加载和损失运算源码不变。启动脚本使用已激活环境中的 Python，方便迁移到 A100；推理改用训练实际保存的配置，避免默认参数更新影响旧实验。旧验证记录对应其各自保存的配置。

对照基准：作者提交 `2309126956d2b80a95f2d307d85a50799cc658a6`。修改发生在本独立工程，原始 `upstream/` 没有修改。`reference/upstream/` 保存完整公开文件，`provenance/source_manifest.json` 记录原件和交付源码的 SHA256。

## 必要修复与数据适配

| 位置 | 原实现 → 本工程 | 为什么需要 | 对结果的影响 |
|---|---|---|---|
| `model.py` 投影损失 | `fake_proj[y,x]` → `fake_proj[:,y,x]`，真值同样修复 | 投影实际是 `(C,H,W)`，旧索引把 y 用于 C=1 的通道轴；ROI 起点非零时得到空张量和 NaN | 明确修复计算错误；得到作者意图下的 ROI 投影 L1，而不是保留 NaN 行为 |
| `wavelets.py` 的 `DWT_2D/IDWT_2D` | 有 CUDA 就 `.cuda()` → 用输入张量的 device/dtype 创建矩阵 | 原实现 CPU 调试或第二张 GPU 运行可能设备不一致，float64 输入也不兼容 | Haar 系数、矩阵构造和自动求导公式不变；有限精度误差受 dtype 影响。未把小波替换为另一个库 |
| `data.py` 轴适配 | 服务器 `ZYX` → 模型 `YXZ` | 作者 loader 注释 `[400,400,640]` 把轴向深度放末轴；服务器数据放首轴。不能直接把 Z 当作其第一个空间轴 | **根据注释采纳 YXZ 是明确假设**，作者未公开原始打包脚本，无法证明其所有实验文件实际方向。输出统一转换回 ZYX |
| `data.py` 读取入口 | 按 `train/validation/test` 文件夹枚举 → 读取服务器 CSV | 数据已经集中存储且有固定划分，不必复制大型数据或重划分 | 保留你已有病例、疾病分层和重复组安排；不宣称名单等于论文名单 |
| `data.py` 有效性检查 | 未检查范围/轴/常量 → 加三维同形状、有限值、0–255、轴和常量裁剪检查 | 原 min–max 对常量体会除零；错轴和错单位应在训练前被发现 | 非法数据明确报错，未静默填零、丢弃病例或重定义强度归一化 |
| `requirements.txt` | 宽泛依赖范围 → 核心版本固定，并补 `einops/PyWavelets/SimpleITK` | MONAI 默认网络随版本可能改变，作者依赖表遗漏实际运行依赖；服务器新环境实测暴露缺少 einops | 明确锁定本工程的实现版本，保留已有训练环境 |
| 包内相对导入 | 作者 `util.*` → 本工程 `.wavelets/.roi` 等 | 使工程可独立部署，避免意外导入其它方法的同名模块 | 仅组织变化 |

### 共享数据已经改变了什么

服务器数据在本次工作前，已经将原始 Z=640 重采样为 Z=256，并保存为未归一化的 float32。本工程只使用该现有版本，不重新处理原始 BMP。这意味着离线轴向插值协议已经由你的公共数据版本决定，不能再声称等于“原始 BMP 直接经过作者 TorchIO Resize”的所有细节。

在此基础上仍保留作者在线流程：`YXZ → TorchIO Resize(400,400,256) → 共同裁剪 256³ → 训练时约 50% 翻转最后轴 Z → OCT/OCTA 分别对当前裁剪做 min–max 到 [0,1]`。验证和测试使用中心裁剪，关闭翻转。3M 横向会从 304 放大到 400 再裁剪，6M 从 400 裁剪；**没有擅自改为原横向分辨率或全视野滑窗**。

最后轴翻转对应 Z，解剖意义需要谨慎；这里为了对照公开代码保留，没有未经说明改成横向翻转。

## 显存执行方式：改变计算组织，保留全部监督样本

| 设置 | 作者 → 默认配置 | 理由和边界 |
|---|---|---|
| 主干执行 | 默认恢复 64 张片一次过网络；可显式选择 `network_chunk=4`，分批并做激活重计算 | 可选的 24GB 3090 适配，降低保存的中间激活。64 个抽片索引、每片 t、终点、损失 ROI、所有 128 个对比特征与 64 张片的最大投影仍统一计算，不把对比损失拆成小批平均 |
| 推理执行 | 默认恢复每批最多 32 张；可显式选择 `inference_chunk=4` | 可选的低显存执行；每片都经过完整固定三步 Euler，不拼接空间 patch，不混合不同病例 |
| 数值边界 | 原批量 FP32 → 另一个批量形状的 FP32 | 网络使用每样本 GroupNorm/attention，没有 BatchNorm 和启用的 dropout，因此数学目标不变；浮点归约顺序不同，**不保证权重轨迹逐位一致**。Adam 对接近零的偏置梯度可能放大细微误差 |
| 关闭方式 | — | 训练加 `--network-chunk 0`，推理批量加 `--inference-chunk 32`。`--train-slices` 默认为 0，表示严格使用 `D//4=64`；手动减少会改变方法的采样/对比/投影，不是等价的显存优化 |

数值测试比较完整目标和梯度，而不是把“参数逐位相同”作为不成立的保证。单步正式尺寸的实际显存/速度见 `verification/benchmark_*_256.json`。

此前关闭网络分批，在空闲的第二张 3090 上按 64 张片整批训练，出现 CUDA 显存不足；当时 PyTorch 已分配约 22.11 GiB，随后再申请 1 GiB 失败。证据为 `verification/benchmark_3m_unchunked.json/.log`，本次整批重试另列在 `VERIFICATION.md`。显式启用分批重计算后，旧 3M/6M 正式尺寸单步曾完成反向更新，峰值约 4.38 GiB。没有完整收敛对照能够证明分批会明显提高或降低最终指标；关闭它是为了减少对照复现中的执行差异。

## 训练预算与运行管理

| 改动 | 理由 | 影响 |
|---|---|---|
| 配置默认 200 epochs，作者脚本默认 400 | 论文 §4.1 明确训练 200 轮；同时记录公开实现冲突 | 会改变训练预算。加 `--epochs 400` 可以对齐作者脚本默认。本工程没有谎称二者相同 |
| 固定 seed=2026，记录配置/环境/清单/源码指纹 | 原入口不保存随机种子，难以重复实验 | 明确新的随机实现；不会还原作者未知的种子 |
| 新训练/验证/预测入口，显式 `train()/eval()` | 工程化完整流程，避免验证使用错误模式 | 默认网络没有启用的 dropout/BatchNorm；不新增模型条件 |
| 一个完整 checkpoint 代替两个仅权重文件 | 原 `continue_train` 仅加载网络，没有 Adam 和随机状态；默认 latest 文件也不存在 | 保存并恢复生成器、对比头、Adam、轮次、随机状态和 loader 状态；epoch 边界恢复，不是假装支持 batch 中途恢复 |
| 每轮 latest、验证 PSNR 最优 best、每 10 轮快照 | 文件可预测、磁盘开销可控、测试不依赖手动猜长标签 | 验证集仍用于按 PSNR 选择模型，测试集不参与选择 |
| 非有限 loss 直接报错，不做更新 | 避免 NaN 权重污染 checkpoint | 未改有限 loss 的数值，未增加梯度裁剪 |
| CPU/单卡显式选择，batch_size 强制 1 | 第二张 GPU 可独立运行；原投影会在 batch>1 时混合患者 | 论文/作者默认也是病例 batch=1；没有冒充多卡实现 |

没有加入 scheduler、AMP、额外正则、预训练权重、数据去噪、配准、展平或 ROI 分割。训练轮数按照扫描体计数，抽到的二维片不是额外独立病例。

数据加载默认 workers 从作者的 4 改为 0，方便在两端调试，并把裁剪/翻转随机状态纳入可验证的恢复过程；支持在配置中明确改回多 worker，并为每个 worker 设置种子。开启确定性计算、关闭 cuDNN benchmark，可能影响速度和浮点归约方式，不保证还原作者未知的执行算法。依赖表去掉核心流程没有调用的 `torchvision/opencv-python/lpips/clean-fid`，不因此声称实现了论文缺失的感知指标评估。

## 评价与输出：新补的明确协议

作者公开仓库缺少完整论文评估项目。本工程补齐 MAE/PSNR/SSIM、轴向最大投影指标、逐病例 CSV、分疾病汇总和可视化；具体定义如下：

- `data_range=1`；体指标是三维数组上的 MAE、PSNR、SSIM；SSIM 窗口固定 7，默认 skimage 均匀窗口，其余设置使用锁定版本默认值。
- 沿物理 Z 最大投影后的二维图另计三项指标。**它与训练中的抽片 batch 最大投影不是同一操作。**
- 只评价作者流程的 resize 后中心裁剪，并记录几何和归一化范围；不把结果标成完整 FOV 或原始分辨率。
- PSNR 在精确零误差时以 float64 epsilon 为 MSE 下限，避免 JSON 中出现 Infinity；非零误差正常计算。
- 每扫描体等权汇总均值/总体标准差；现有清单使用公开病例号作为患者代理，不据此证明真实自然人完全独立。
- 不新增未经作者验证的 foreground 阈值，不将最大投影称为有解剖标签的分层投影，不用不明来源权重补 LPIPS/FID 或诊断评估。

作者 `calculate_psnr_3d/ssim_3d` 使用 GT 动态范围；在其裁剪后非恒定 min–max 数据上范围也是 1。这里把它明确固定并校验，避免未来输入范围变化造成指标悄悄改变。

## 明确保留的论文/代码差异

这些没有擅自“修正”，否则交付会变成一个新的方法：

1. 公开代码是 **2D** MONAI 速度 U-Net 与 **2D** Haar 小波；四通道是 LL/LH/HL/HH。不是完整三维生成器或 3D 八子带小波。
2. 网络输入仅为当前插值状态的小波通道与 t；固定 OCT 没有额外拼接作为独立条件。
3. 训练沿模型第一空间轴抽片；按本文 YXZ 假设即 Y/B-scan 位置，不能直接称作沿 Z 的视网膜深度对齐。
4. 训练投影是在所抽二维片的合并 batch 上取 max；batch=1 时对抽到的 Y 片投影，得到 XZ 平面。不是全 Z、全体积或带层标签的 en-face 投影。
5. 对比头和损失保持作者的全局池化、128 维特征、温度 0.1、对称 InfoNCE；不是自行补写带层标签的 RDCA。
6. 损失 ROI 保留作者基于预测/真值边界框并集的规则，不把它改成新血管 mask；速度在 IDWT 后的像素域计算裁剪 MSE。
7. 原权重保持 `10*velocity + 0.5*L1 + 0.005*contrast + 0.1*projection`。论文将 voxel/layer 项合并后的系数不能直接替换该表达式。
8. 三步 Euler 从 OCT 状态出发，每一步 clamp 到 [0,1]；保留原推理行为。
