**二、数据用了什么，经过了哪些处理**

使用现有公共数据 `OCTA500_common_v1`；你在A100上将其存为 `/workspace/flowoct_work/data/OCTA500_v1`。训练入口读取其中的CSV和 `z256` 配对NPZ，不依赖未上传的 `native` 文件夹。

| 数据环节 | 实际处理及影响 |
|---|---|
| 原始数据 | 3M原始体积为640×304×304，6M为640×400×400，以下体积尺寸按ZYX描述 |
| 已有离线公共数据 | 仅沿Z把640线性重采样至256；无抗混叠滤波；保存float32，强度仍为0–255；不包含新的去噪、配准、展平或解剖ROI裁剪 |
| 本次加载适配 | 将存储的ZYX转为模型使用的YXZ；依据作者loader中 `[400,400,640]` 的末轴深度注释作此适配，作者原始打包脚本未公开，方向仍属于明示假设 |
| 在线尺寸处理 | OCT和OCTA分别经过作者的TorchIO `Resize(400,400,256)`，再使用相同坐标裁剪256³ |
| 训练增强 | 随机横向裁剪；按作者代码约50%概率翻转末轴。当前轴定义下末轴是Z，保留了此行为，没有自行换成横向翻转 |
| 验证与测试 | 固定中心裁剪，不翻转；中心起点为YXZ的 `[72,72,0]` |
| 强度归一化 | OCT与OCTA各自对当前裁剪执行min–max至[0,1]；常量、非有限值、错范围或错形状明确报错 |
| 输出 | 预测保存回ZYX轴顺序，仍为归一化的256³中心体块；没有恢复640深度或完整横向视野 |

3M横向先从304插值至400，再取256中心区域。因此每个横向轴仅覆盖原视野约64%，即3mm扫描的中心约1.92mm范围。“全深度FULL投影”只表示覆盖这个体块的全部Z深度，不表示恢复完整3mm×3mm视野。

数据划分沿用已有固定、按疾病分层的CSV，没有为了本次结果重新选病例或重划分。划分数量与论文一致，但具体病例ID不能宣称与作者相同。读取时检查病例号、路径、患者代理ID及 `leakage_group` 是否跨集合；已知重复图像10333/10388仍共同保留在训练集。公开病例号被用作患者代理，不能据此证明全部自然人身份关系。

这份数据已在本次训练前完成Z向插值，随后再走作者在线流程；尚无证据证明它与“作者原始BMP封装后直接预处理”的全部细节相同。论文提到的视网膜区域裁剪也未完整公开，当前几何中心裁剪不能直接声称等同于作者的解剖裁剪。

**三、模型和训练目标如何实现**

沿用作者的MONAI二维 `DiffusionModelUNet(spatial_dims=2, in_channels=4, out_channels=4)`，没有换成自行设计的三维网络。虽然输入与最终输出是体积，主干仍逐二维切片计算。四个通道为二维Haar小波的LL、LH、HL、HH；小波尺寸由256×256变成128×128。

生成器参数为 **2,330,180（约2.33M）**。训练还使用 **8,960** 参数的对比头，合计 **2,339,140** 个可训练参数；推理生成只使用生成器，不使用对比头。

一次训练更新的过程为：

1. 从一个256³病例按作者规则抽取第一空间轴长度的四分之一，即64张二维片；当前YXZ约定下抽取的是不同Y/B-scan位置，片内为XZ。
2. 每张片采样时间 `t`，以OCT为起点 `x₀`、配对OCTA为终点 `x₁`，构造 `xₜ=(1−t)x₀+t x₁`，监督速度为 `x₁−x₀`。
3. 对当前状态做二维Haar变换，将四子带与时间t送入作者速度网络，再逆变换为像素域速度。
4. 由速度估计终点OCTA，裁剪到[0,1]，计算四项损失，统一反向传播和Adam更新一次。

网络没有额外拼接固定OCT条件通道；OCT通过插值状态和推理起点参与生成。没有改成从高斯噪声出发的另一种生成方法。

总损失保持作者公开代码：

`L = 10 × L_velocity + 0.5 × L_L1 + 0.005 × L_contrast + 0.1 × L_projection`

| 损失 | 实际定义 |
|---|---|
| 速度 | IDWT后的像素域速度与目标速度，在作者自动裁剪区域内计算MSE |
| 重建 | 估计终点与GT，在作者自动裁剪区域内计算L1 |
| 对比 | 64个预测及64个GT，经作者全局池化对比头得到128维特征，统一计算温度0.1的对称InfoNCE |
| 投影 | 对抽到的64张二维片沿合并的切片batch取最大值，再在自动裁剪区域计算L1 |

自动裁剪工具原样保留：按信号阈值寻找预测与真值的包围框并取并集，纵向增加10像素边界。其默认阈值比例0.05来自作者代码。它不是新增的血管分割掩膜，也不等于论文所描述的三维GT前景掩膜。

**训练投影尤其需要区分：当前实现沿抽到的Y片取max，产生XZ平面；它与评价时沿物理Z生成的en-face投影不同。** 按你确定的公开代码基准，没有将其改写为解剖分层投影，或新增带层标签的对比损失。论文与代码的损失表达和权重体系存在差别，本次保留公开代码中的四项定义和系数。

**四、A100正式训练的实际配置**

下表来自下载的 `prediction.json` 中保存的运行配置和环境，不仅是本地默认配置。

| 参数 | 本次3M实验实际设置 |
|---|---|
| GPU | NVIDIA A100 80GB PCIe，单卡 |
| 环境 | Python 3.10.22；PyTorch 2.5.1+cu121；MONAI 1.4.0；TorchIO 0.20.4；NumPy 1.26.4 |
| 训练预算 | 200 epochs；当前可核验完整100轮 |
| 病例batch | 1；每轮遍历140个训练病例，即每轮140次更新 |
| 训练抽片 | 每病例64张；`train_slices=0`表示使用作者 `D//4` 规则 |
| 主干执行 | `network_chunk=0`，64张整批前向，不调用激活重计算 |
| 精度 | FP32；没有AMP、梯度裁剪或额外正则 |
| 优化器 | Adam，学习率0.0002，betas=(0.5,0.999)，没有学习率调度 |
| 初始化 | 从头训练，无预训练权重 |
| 随机性 | seed=2026；确定性计算；关闭cuDNN benchmark |
| 数据加载 | workers=0，CPU线程数4 |
| 验证频率 | 每轮对10个验证病例进行完整生成与评价 |
| 推理 | 从OCT出发，固定3步Euler，每步clamp至[0,1]；每批最多32张片，覆盖体块全部切片 |

早期为了24GB 3090加入过 `network_chunk=4` 与激活重计算，3M/6M单步运行曾通过，峰值allocated约4.38GiB。按你的要求，正式配置随后恢复整批；3090两次整批测试均显存不足，一次失败时已分配约22.11GiB、再申请1GiB失败。

**这次A100前100轮并未使用那条分批重计算分支。** 该分支和可选抽片参数仍留在源码便于审阅，实际运行配置确认未启用。A100日志中的训练峰值allocated约25.17–25.18GiB，与3090的容量限制相符；这只是PyTorch分配统计，不是系统全部显存占用。

100轮日志中训练加验证平均约9.17分钟/轮，累计约15.28小时，不含停机、初始化和部分存盘开销。每轮包含140次训练更新与10例三步验证；参数少不意味着总训练工作量少。workers=0和确定性计算可能影响吞吐，目前没有性能剖析证明某一项是主要瓶颈。

**五、与原始代码相比，具体修改了什么**

| 修改项 | 本次实现 | 理由与复现影响 |
|---|---|---|
| 投影损失ROI索引修复 | 对预测与GT均将 `[y,x]` 改为 `[:,y,x]` | 原投影为(C,H,W)，漏掉通道会在ROI非零起点产生空区域、NaN；这是明确的计算错误修复，会改变原错误分支的数值行为 |
| 小波设备与类型修复 | DWT/IDWT矩阵跟随输入device和dtype创建 | 支持CPU检查及指定GPU，避免作者直接 `.cuda()` 导致设备不一致；Haar系数、矩阵构造和自动求导公式保留 |
| 数据入口改写 | 文件夹枚举改为CSV配对清单，增加ZYX→YXZ轴适配 | 使用既有数据和固定划分；方向选择有依据但不能证明与作者未公开封装完全相同 |
| 输入有效性检查 | 检查形状、有限值、0–255范围、轴元数据及常量裁剪 | 在训练前暴露配对或归一化错误，不静默填零、丢病例或改变合法数据 |
| 显存选项 | 加入可关闭的网络分批重计算及抽片数选项 | 早期适配3090；当前正式实验关闭分批，保持64片。没有完成200轮的整批/分批收敛等价证明 |
| 非有限loss检查 | 反向传播前发现NaN/Inf就停止 | 防止损坏权重，不改变有限loss或增加梯度裁剪 |
| 训练总轮数 | 作者脚本默认400，当前正式配置200 | 采用论文§4.1及你确定的200轮预算；这是明确的预算选择，不把两种设置称为相同 |
| 随机与加载方式 | 固定seed=2026，workers由作者4改为0，启用确定性计算 | 便于检查与恢复；可能改变速度和数值轨迹，不还原作者未知的随机种子 |
| 权重加载与恢复 | 绕开模型构造时的两文件自动加载，改为runner恢复完整checkpoint | 原实现仅加载生成器/对比头权重，不能完整恢复Adam和随机过程；本工程支持epoch边界续训 |
| 验证与保存流程 | 新入口显式切换train/eval，统一记录逐步损失、每轮验证及保存规则 | 使训练、选模、测试与恢复可追溯，不新增生成条件或改变网络结构 |
| 环境与包组织 | 固定核心版本，补足einops等实际依赖，使用包内导入 | 锁定MONAI默认网络与运行环境，避免调用其他项目的同名模块；未调用的LPIPS/FID依赖未作为已完成评价 |
| A100部署入口 | 新增 `a100.py`、数据路径自动定位、检查/训练/恢复/测试入口 | 数据目录改名或位置变化后无需改源码和JSON；只处理路径、设备及调用流程 |
| 评价与记录 | 新增明确的MAE/PSNR/SSIM、逐病例/疾病组汇总、可视化与来源指纹 | 这是本工程补充的评价协议，不能自动视为论文未公开完整评价实现 |
| FULL后处理修正 | 原Z向max之外，独立补算Z向mean并对齐方向、裁剪和显示窗口 | 对齐你指定的OCTA-500 FULL展示；不改训练投影损失、模型、权重或原最大投影指标 |

`model.py`相较作者文件实际有6类修改块：导入、移交自动恢复、抽片选项、可选分批分支、投影ROI索引、非有限损失检查。因此不能称为“模型文件一行没改”；可以确认的是主干配置、Haar定义、核心插值与生成过程，以及四项损失及权重保持公开代码。

作者ROI工具与小波自动求导文件逐字节保留。逐行差异见 `flowoct_reproduction/provenance/*.patch`，全部新增代码汇总见 `EXTRA_CODE_REVIEW.md`。本次未添加数据去噪、配准、视网膜展平、新前景阈值、额外训练数据、预训练模型、AMP、调度器或多卡训练。

完整checkpoint包含生成器、对比头、Adam、已完成轮次、global step、最佳分数、Python/NumPy/Torch/CUDA随机状态，以及DataLoader随机状态。保存采用临时文件后替换。只支持epoch边界恢复；中途停止会从上一轮末尾重跑未完成轮次。

恢复要求使用原run的 `latest.pt`，校验原配置和清单；只允许明确调整总轮数或设备，不会把旧分批实验静默改成整批实验。相同软件和同卡下的32³短程测试验证过连续两轮与中断恢复后的网络张量和Adam状态一致；未承诺跨GPU、跨版本逐位一致，也未把该测试当成分批与整批等价的证据。

当前第98轮最佳模型是在查看测试集之前，根据验证集平均体积PSNR **28.9526dB** 选出的；并非看了50例测试结果才挑98轮。后来按你的要求对98与100轮作中期测试对比。测试集已被用于阶段性查看，后续配置和模型选择仍应依据训练/验证数据，保留本次查看记录。

**八、评价口径及FULL显示修正**

当前体积指标比较同一个归一化256³中心裁剪上的预测与GT；MAE和PSNR使用全部体素，SSIM在三维数组上计算。固定 `data_range=1`、SSIM窗口7；按病例等权统计均值和总体标准差。标准差反映病例差异，不是多次随机训练的波动。

必须分清以下四种对象：

| 名称 | 实际对象 | 能否互相替代 |
|---|---|---|
| 训练投影损失 | 抽取的64张Y片取max，得到XZ面 | 不能称为官方FULL或物理Z向en-face投影 |
| 本工程最大投影评价 | 对输出ZYX体积沿物理Z取max，得到YX平面 | 可作另一种观察，但不是官方OCTA FULL |
| OCTA-500 FULL图 | 沿全部物理Z取算术平均；显示转为与官方BMP一致的XY | 是此次用户指定的图像展示口径 |
| FlowOCT论文表格的full volume | 全体积评价，与foreground region并列 | 不等于OCTA-500的FULL平均投影指标 |

OCTA-500原论文§3.3的B4明确FULL采用轴向均值，B5/B6分层投影采用最大值。[来源](https://arxiv.org/pdf/2012.07261)

此前我提供的是全深度max，并以[0,1]固定窗口展示，未充分对齐你所说的官方FULL。发现这一差异后，我使用同一份第98轮预测补算50例均值投影，转置显示方向，将官方BMP对齐到相同中心区域；未重训或重新选模型。

GT与预测图共用由GT最小值至第99百分位确定的显示窗口，另保留固定[0,1]显示用于核对，未分别拉伸两图。官方BMP仅作为视觉参考；指标比较未拉伸的归一化预测均值与GT均值，不直接以带有官方显示映射的BMP作为数值目标。

**九、当前第98轮的50例测试结果**

| 评价对象 | MAE，均值±总体标准差 | PSNR，均值±总体标准差/dB | SSIM，均值±总体标准差 |
|---|---:|---:|---:|
| 256³体积 | 0.013565 ± 0.002842 | 28.8894 ± 0.9368 | 0.8404 ± 0.0796 |
| 全深度最大投影 | 0.080618 ± 0.015577 | 19.9300 ± 1.4895 | 0.3252 ± 0.0430 |
| 全深度FULL平均投影 | 0.007507 ± 0.002684 | 40.9105 ± 2.2487 | 0.9279 ± 0.0348 |

均值投影会平滑轴向误差，其强度动态范围通常较小，固定 `data_range=1` 也会影响PSNR与SSIM的数值水平。因此40.91dB不能与最大投影的19.93dB或论文的全体积PSNR直接比较，更不能解释为模型经过显示修正后提升了约21dB。

第100轮同一50例的体积PSNR为28.3665dB、SSIM为0.6838；第98轮整体更好，符合按验证集选模的现有规则。仅两轮差异不能证明持续过拟合，也不能保证再训练100轮一定改善。

测试集中NORMAL 40例、DR 8例、AMD 1例、CNV 1例，总均值主要受正常病例影响。少数疾病各1例，不能据此证明相应疾病的泛化能力。观察到部分主要结构对应，但细血管模糊、局部结构不匹配及过亮病例仍存在；FULL平均投影的高分不能替代血管连续性或病灶恢复的定量验证。

**十、当前结论与后续安排**

当前证据支持：代码与训练/推理/恢复流程有效，模型学到了部分OCT→OCTA映射；当前结果为在明确公共数据协议上的作者公开实现阶段性复现。

以下因素仍妨碍宣称严格复现论文全部数值：实际病例划分未知是否相同、已有Z向插值与作者离线流程未完全对齐、轴顺序依赖公开注释、解剖视网膜裁剪未唯一恢复、论文与公开代码的损失/对比/投影实现存在差异，以及训练预算尚未在当前记录中完成。尚未补齐作者完整的前景、解剖分层、LPIPS、FID及下游诊断评价，也没有多随机种子实验或使用同协议完成的全部基线比较。

后续按已确定方案保持数据、源码和损失设置，从 `latest.pt` 续训至总200轮，继续由验证集平均体积PSNR选择 `best.pt`，最终统一评价并保留本次中期记录。是否充分收敛需看后续验证曲线；即使200轮内最优仍为98轮，也应如实报告。

**可用于口头汇报的表述**

本次以FlowOCT作者公开二维代码为基础，在现有OCTA-500统一数据划分上搭建了可训练、可恢复和可评价的复现工程。我们保留了二维Haar小波、MONAI速度U-Net、四项损失及三步Euler推理；修复了投影ROI通道索引和小波设备处理，并适配现有NPZ轴顺序及CSV清单。正式实验在A100 80GB上使用64张切片整批FP32训练，未启用早期3090适配的分批重计算。当前已核验100轮，最佳模型由验证集在98轮选出，50例测试体积PSNR为28.89dB、SSIM为0.8404。后处理核对发现官方FULL采用均值而非最大值，已在不改权重的情况下纠正展示与补算指标。当前流程有效且部分结构得到恢复，但数据预处理、论文未公开评价及200轮训练预算仍需明确其完成程度。
